## Текущее состояние

**Где остановились:** Найдена и устранена причина «Не удалось подключиться. Проверено: 6 шлюзов» — на машине заклинил WMI (служба `Winmgmt` зависла в `STOP_PENDING` внутри защищённого `svchost`, провайдер `WmiPrvSE` не отвечает). Все скрипты VPN Gate держались только на WMI-командлетах, поэтому демон шлюзов умер, автоподключение считало живые шлюзы мёртвыми, а панель «Приложения без VPN» висела. Переписаны на работу без WMI: добавлены `payload/netutil.ps1` (состояние сети из `System.Net.NetworkInformation`, `route print -4`, `netstat -ano`) и `payload/netcompat.ps1` (те же cmdlet-имена, но без WMI), на них переведены `keep-gateways.ps1`, `vpn-auto.ps1`, `split-tunnel.ps1`, `route-guard.ps1`. Добавлен `payload/repair-wmi.ps1` — починка WMI, если она заклинит снова. Схема работает при мёртвом WMI, но сам WMI на машине ещё не воскрешён: для этого нужна перезагрузка Windows, которую пользователь делает сам.

**Что проверено:** При живом (мёртвом) WMI: `split-tunnel.ps1 -Status` отвечает за 30 с и показывает VPN `10.211.1.60`, метрики маршрутов 2/25/65, keep-gateways и route-guard работают. `vpn-auto.ps1` подключился к `83.110.98.6:443` (первый known-good, TCP-зонд нашёл 19 живых из 258), внешний IP стал `83.110.98.6` — трафик пошёл в туннель; в таблице маршрутов `0.0.0.0/0 → 10.211.254.254` с эффективной метрикой 2 впереди физических 25/65 и persistent 30. Машинная приёмка TrafikRuler: временное правило для `C:\Windows\System32\curl.exe` на «Беспроводная сеть» → `curl.exe https://api.ipify.org` вернул домашний `31.163.153.159`, тогда как трафик без правила шёл через VPN Gate `83.110.98.6`; правило после проверки удалено. Перезагрузка Windows после правок не выполнялась — поведение схемы на чистой загрузке не проверено.

**Следующий шаг:** Пользователь перезагружает компьютер. После загрузки: `powershell -NoProfile -ExecutionPolicy Bypass -File "C:\ProgramData\VPNGateSetup\repair-wmi.ps1"` от администратора (если WMI снова не отвечает), затем ярлык «VPN Gate — Включить», затем проверить, что в окне «VPN Gate — Окно» блок «Приложения без VPN» показывает рост счётчика `direct` у программы с правилом.

**Не повторять:** Не диагностировать «не подключается» через `Get-NetAdapter`/`Get-NetRoute` — на этой машине WMI заклинивает, и именно эти вызовы были причиной отказа. Не парсить вывод `netsh`/`ipconfig`/`route print` по названиям колонок: утилиты печатают заголовки на языке системы, данные разбираются только по позициям. Не запускать внешние утилиты без таймаута: `netsh` зависал намертво и блокировал демон шлюзов на минуты. Не подставлять шлюз `0.0.0.0`. Не поднимать два профиля SoftEther одновременно.

## Задача 2 — Переключение шлюзов по кругу — 2026-11-14

**Агент:** DeepSeek V4.1 Flash в OpenCode

### Запрос пользователя
> Смотри отчет D:\GitHub\KVNGate\.work-report\REPORT.md. Мне нужно сделать так чтобы можно было переключать VPN соединения не только на Францию и Эмираты, а еще и другие. Потому что сейчас если я в виджете выбираю переключиться к следующему он переключает на Эмираты, а затем если находясь на Эмиратах нажимаю переключить, то переключает на Францию и обратно... таким образом переключение цикличное, а мне надо дальше. Я не для того пропускаю Францию чтобы потом посла ОАЭ снова на нее преключится, т.к. она свободная для подключения.

### Что сделано
- Найдена причина качелей France ↔ UAE: кнопка «Следующий шлюз» передавала в `vpn-auto.ps1` только `-SkipEndpoint <текущий IP>`, а каждый новый запуск заново строил список с начала. Поэтому после пропуска Франции первым шёл ОАЭ, после пропуска ОАЭ снова первой оказывалась Франция.
- В `vpn-auto.ps1` добавлен ключ `-Rotate`. Посещённые IP сохраняются в `%LOCALAPPDATA%\VPNGateAuto\rotation.txt` вместе с номером круга и общим числом шлюзов. Из списка кандидатов убираются все IP текущего круга; когда они заканчиваются, круг автоматически начинается заново. Ключ пробрасывается и при самоповышении прав.
- При первом запуске новой версии (файла `rotation.txt` ещё нет) все шлюзы из `known-good.txt` считаются пройденными. Это те серверы, которые уже подключались; иначе первый же клик снова вернул бы на France/UAE, а не увёл на новую страну.
- В отчёт для окна добавлены поля `rotationRound`, `rotationSeen`, `rotationTotal`. В `vpn-ui.ps1` кнопка «Следующий шлюз» передаёт `-Rotate`, а строка «Сессии SoftEther» показывает `круг 1 · шлюз 7 из 86`. Подсказка внизу окна дополнена, высота подсказки и лога поправлены под новую строку.
- `Show-Report` в окне обновляет подпись круга и для неудачной попытки, чтобы старый прогресс не висел после ошибки.
- В меню трея добавлен пункт «Начать круг заново»: он пишет пустой `rotation.txt` с `round=1`, чтобы следующий клик снова начал с проверенных шлюзов, а не считал их пройденными.
- Обновлены README в репозитории и живой папке.

### Как проверить
- Закрыть текущее окно через трей → Выход и открыть ярлык «VPN Gate — Окно» заново.
- Нажать «Следующий шлюз». Ожидание: подключение к новой стране (в текущем кэше первым идёт United States), в строке «Сессии SoftEther» — `круг 1 · шлюз N из M`. Повторное нажатие — следующая страна (India, Australia…), а не возврат на France/UAE.
- `powershell -NoProfile -ExecutionPolicy Bypass -File F:\z.ai\Custom\vpngate-auto\vpn-auto.ps1 -Inventory -ReportPath $env:TEMP\vpngate-inv.json` при `VPNGATE_NO_ELEVATE=1` — в JSON должны быть `rotationRound`, `rotationSeen`, `rotationTotal`.

### Решения и допущения
- Круг хранится по IP, а не по `IP:порт`: иначе один и тот же сервер возвращался бы на другом порту и страна не менялась.
- Первый клик после обновления намеренно пропускает все записи `known-good.txt`: это ровно те шлюзы, которые уже использовались и давали France ↔ UAE. Новый круг начнётся после прохода остальных.
- Круг общий для всех стран, без отдельного файла на каждую. При `-Country` фильтр стран всё равно оставит только выбранные, а счётчик покажет только их.
- Сброс круга — пункт трея «Начать круг заново»: он пишет пустой `rotation.txt` с `round=1`, и следующий клик снова берёт проверенные шлюзы сверху.
- Старый режим `-SkipEndpoint` без `-Rotate` оставлен без изменений для совместимости.

### Открытые вопросы и риски
- Живой клик по «Следующему шлюзу» в новом окне ещё не делался: окно нужно переоткрыть, старый процесс работает со старым кодом.
- На этой машине сейчас `VPNGATE_AUTO` Offline (UAE), поэтому первый клик может сразу подключить новую страну, а не переключать текущую.
- Выбор конкретной страны в окне по-прежнему недоступен; для этого остаётся `-Country JP,KR` в консоли. Если понадобится, можно добавить выпадающий список стран.
