# KVNGate

Бесплатный VPN на Windows через публичные шлюзы [VPN Gate](https://www.vpngate.net/). Клиент — SoftEther VPN Client, плагин VPN Gate входит в него. Покупать сервер не нужно.

Программы, которым нужен обычный домашний интернет, отделяются от туннеля по имени exe. Это делает TrafikRuler. Остальной трафик идёт через VPN.

Другой нейронке эту папку отдают с фразой: «прочитай `AGENT.md` и разверни VPN на этом компьютере».

## Схема

```
программа без правила  ──► SoftEther VPN Gate ──► интернет (адрес шлюза)
программа с правилом   ──► Wi-Fi или кабель     ──► домашний интернет
```

Пока VPN включён, маршрут по умолчанию ведёт в туннель. `vpn-auto.ps1` включает у профиля `VPNGATE_AUTO` флаг `NOTRACK`, поэтому SoftEther больше не удаляет шлюзы Wi-Fi и кабеля. `payload/keep-gateways.ps1` всё равно держит оба маршрута: физические с метрикой 30 и VPN с метрикой 1. Без физического шлюза правило «ходи только через Wi-Fi» оставило бы программу без интернета. `NOTRACK` применяется после переподключения профиля — `vpn-auto.ps1` делает это сам.

Windows так не умеет: её маршруты смотрят на адрес назначения, а не на программу. Две программы на один и тот же IP развести маршрутом нельзя. Поэтому разделение делает TrafikRuler (перехват пакетов конкретного exe), а не таблица маршрутов.

Одновременно можно держать только один туннель SoftEther. Второй профиль забирает маршрут по умолчанию и рвёт первый.

## Что в комплекте

| Файл | Зачем |
|---|---|
| `install.ps1` | ставит клиент и .NET, если их нет, копирует файлы, создаёт ярлыки и задачи `VPNGateKeepGateways` и `TrafikRuler` |
| `AGENT.md` | пошаговое задание для нейронки, которая ставит это на чужом компьютере |
| `payload/vpn-auto.ps1` | сам находит живой шлюз VPN Gate и подключается. Профиль `VPNGATE_AUTO`, `NOTRACK` |
| `payload/split-tunnel.ps1` | правила TrafikRuler и панель: список программ, включение, добавление exe, выбор адаптера, диагностика |
| `payload/VPNGateAuto.bat` | ярлык «Включить» |
| `payload/VPNGateOff.bat` | ярлык «Выключить» — гасит только `VPNGATE_AUTO` |
| `payload/VPNGateStatus.bat` | ярлык «Статус» |
| `payload/VPNGateUI.bat` | окно VPN и блок «Приложения без VPN» |
| `payload/keep-gateways.ps1` | держит default-маршруты физических адаптеров и VPN |
| `payload/netutil.ps1` | состояние сети без WMI: адаптеры, адреса, шлюзы, DNS, маршруты, соединения |
| `payload/netcompat.ps1` | те же cmdlet-имена (`Get-NetRoute` и т.п.), но источник — не WMI |
| `payload/repair-wmi.ps1` | починка WMI, если он заклинил |
| `payload/route-guard.ps1` | старый сторож маршрутов; приложения не трогает, запускается только как `-NoAppSplit` |
| `payload/TrafikRuler/` | программа правил по exe. GPL-3.0, WinDivert 2.2.2. DHCP не перехватывает, иначе SoftEther не получает адрес — см. `PATCH.md` |

Установщик сам скачивает то, чего нет на машине:

- SoftEther VPN Client 4.44 Build 9807 — [релиз на GitHub](https://github.com/SoftEtherVPN/SoftEtherVPN_Stable/releases/tag/v4.44-9807-rtm), файл `softether-vpnclient-v4.44-9807-rtm-2025.04.16-windows-x86_x64-intel.exe`. Если GitHub недоступен, то же файл с `www.softether-download.com`, каталог `v4.44-9807-rtm-2025.04.16-tree/Windows/SoftEther_VPN_Client/`.
- .NET 8 Desktop Runtime — нужен TrafikRuler: `https://aka.ms/dotnet/8.0/windowsdesktop-runtime-win-x64.exe`.

## Установка

Windows 10 или 11, 64-bit. PowerShell от администратора, из этой папки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Если установщик SoftEther откроет окно, выбрать VPN Client. Server и Bridge не нужны.

После установки:

- файлы лежат в `C:\ProgramData\VPNGateSetup`;
- на рабочем столе ярлыки «VPN Gate — Включить», «Выключить», «Статус», «Окно» и TrafikRuler;
- задача `VPNGateKeepGateways` держит шлюзы физических адаптеров и VPN;
- задача `TrafikRuler` поднимает перехват с правами администратора при входе;
- VPN ещё не подключён.

## Установка на другом компьютере

Комплект переносится целиком: нужны `install.ps1`, `payload\` и `payload\TrafikRuler\`. Без TrafikRuler установка тоже пройдёт, но разделение «программа мимо VPN» работать не будет: весь трафик уйдёт в туннель.

1. Скопировать папку KVNGate на новую машину. Установленный `C:\ProgramData\VPNGateSetup` со старого компьютера не копировать: пути и задачи создаются на месте.
2. Запустить от администратора из папки комплекта:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
   ```
   Установщик ставит SoftEther VPN Client 4.44 и .NET 8 Desktop Runtime, если их нет, копирует скрипты и TrafikRuler в `C:\ProgramData\VPNGateSetup`, создаёт ярлыки и задачи `VPNGateKeepGateways` и `TrafikRuler`.
3. Подключить VPN тем же клиентом SoftEther: через VPN Gate в графическом менеджере или ярлыком «Включить».
4. Открыть «VPN Gate — Окно» и заново добавить программы в блоке «Приложения без VPN», выбрав уже местный адаптер (обычно Wi-Fi).

Список правил не переносится. Он лежит в `%APPDATA%\TrafikRuler\settings.json` и привязан к GUID сетевого адаптера и путям exe, а на другой машине они другие. Правила добавляются заново через панель. Профиль `VPNGATE_AUTO` и флаг `NOTRACK` тоже создаются на месте при первом подключении.

Проверка после переноса: в активных маршрутах VPN с метрикой 1 и физические адаптеры с метрикой 30; `split-tunnel.ps1 -Status` показывает перехват и правила; у программы с правилом внешний IP домашний, у остальных — адрес шлюза VPN Gate.

## Как пользоваться

1. Открыть SoftEther VPN Client Manager и подключиться через VPN Gate к публичному шлюзу. Это основной способ.
2. Ярлык «Включить» — второй способ, тем же клиентом, своим профилем `VPNGATE_AUTO`. Пока графическое подключение уже поднято, этот ярлык не нажимать.
3. «Выключить» гасит только `VPNGATE_AUTO`. Графическое подключение отключают в самом клиенте.
4. Открыть «VPN Gate — Окно» и в блоке «Приложения без VPN» отметить программы, которым нужен домашний интернет. Выбрать адаптер (обычно Wi-Fi) и нажать «Добавить программу». Правило применяется сразу: задача `TrafikRuler` перезапускает перехват без UAC.
5. Уже открытые соединения программы остаются на старом пути. После изменения правила перезапустите программу, чтобы она переподключилась через выбранный адаптер.

`TrafikRuler` не нужно запускать вручную от администратора: задача делает это при входе и при изменении правил. Если задача потерялась, выполните от администратора:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\ProgramData\VPNGateSetup\split-tunnel.ps1" -Bootstrap -NoElevate
```

Те же действия из консоли:

```powershell
cd "C:\ProgramData\VPNGateSetup"
.\split-tunnel.ps1 -Status
.\split-tunnel.ps1 -AddApp "C:\Apps\Opera.exe" -Adapter "Беспроводная сеть" -EnableNew
.\split-tunnel.ps1 -EnableRule "ZCode"
.\split-tunnel.ps1 -DisableRule "ZCode"
```

Ключи `vpn-auto.ps1`, если запускать его напрямую:

| Ключ | Смысл |
|---|---|
| `-Status` | поднят ли туннель и какой внешний адрес |
| `-Disconnect` | выключить профиль `VPNGATE_AUTO` |
| `-Force` | сменить сервер |
| `-Review` | после подключения оставить консоль: пинг, скорость, оставить шлюз или взять следующий. Ярлык «Включить» запускает с этим ключом |
| `-Rotate` | брать следующий шлюз по кругу и не возвращаться к уже пропущенным. Так работает кнопка «Следующий шлюз»; когда круг пройден, начинается новый. Сброс — пункт трея «Начать круг заново» |
| окно `VPNGateUI.bat` | то же самое кнопками: следующий шлюз, замер, отключение. Закрытие окна туннель не рвёт |
| `-Country JP,KR` | пробовать только эти страны |

## WMI на Windows может заклинить

Все сетевые данные скрипты берут **не через WMI**. Раньше они опирались на
`Get-NetAdapter` / `Get-NetRoute` / `Get-NetIPAddress`, а это WMI. 18.11.2026
провайдер WMI на этой машине перестал отвечать, и вызовы начали висеть или
отменяться с `RPC_E_CALL_CANCELED`. Из-за этого:

- демон `keep-gateways.ps1` зависал и переставал возвращать маршрут в туннель —
  VPN был «подключён», но трафик шёл мимо него;
- `vpn-auto.ps1` не мог прочитать адрес адаптера и считал живые шлюзы мёртвыми:
  «Не удалось подключиться. Проверено: 6 шлюзов»;
- панель «Приложения без VPN» не отвечала.

Теперь состояние сети читается через `payload/netutil.ps1`: адаптеры, адреса,
шлюзы и DNS — из `System.Net.NetworkInformation`, маршруты — из `route print -4`,
соединения — из `netstat -ano`. Правка маршрутов и DNS — через `netsh`
(нужен только код возврата). Вывод утилит Windows локализован, поэтому строки
разбираются по позициям, а не по названиям колонок.

`payload/netcompat.ps1` даёт те же имена (`Get-NetRoute` и прочие), но с
не-WMI источником — им пользуется `route-guard.ps1`.

Если WMI заклинил и компьютер надо чинить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\ProgramData\VPNGateSetup\repair-wmi.ps1"
```

Скрипт перезапускает службу `Winmgmt`, при нужде пересобирает репозиторий WMI и
поднимает задачи заново. Если служба застряла в `STOP_PENDING` внутри
защищённого `svchost`, её без перезагрузки Windows не снять — скрипт об этом
напишет. Сама схема VPN Gate при этом продолжает работать: маршруты и правила
TrafikRuler от WMI не зависят.

## Как понять, что схема работает

В активных маршрутах есть `0.0.0.0/0` через адаптер VPN с метрикой 1 и отдельные `0.0.0.0/0` через физические адаптеры с метрикой 30. Запрос к `1.1.1.1` без правила TrafikRuler выбирает VPN-адаптер. Сайт в программе с правилом открывается с домашнего IP, сайт в программе без правила — с адреса шлюза VPN Gate.

`split-tunnel.ps1 -Status` и блок в окне показывают по каждой программе число соединений `direct` и `vpn`. После смены правила старые соединения могут остаться в VPN — перезапустите программу. На исходной машине проверено через `curl.exe`: без правила внешний IP был адресом VPN Gate, с временным правилом на Wi-Fi — домашним адресом провайдера.

## Чего здесь нет

Amnezia в этот комплект не входит. Ей нужен свой сервер за рубежом, и она не замена VPN Gate. Второй туннель поверх SoftEther тоже не запасной канал: если шлюз VPN Gate не поднялся, верхний слой не запустится.

Не включать два профиля SoftEther сразу. Не вешать программам маршруты по их IP. Не ставить шлюз `0.0.0.0`: от этого сеть глохнет.
